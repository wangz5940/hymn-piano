这是目前**整个音乐软件生态最大的短板之一**。

结论先说：

> **五线谱有成熟的渲染引擎（OSMD、VexFlow、Verovio），但简谱几乎没有成熟、现代、开源的 Web 渲染框架。**

所以国内很多钢琴/古筝/电子琴教学 App 的简谱都是**自己写渲染器**。

# 我调研过的几个方案

## ① VexFlow ❌

很多人第一反应就是 VexFlow。

实际上：

> **VexFlow 完全不支持简谱。**

它的数据模型就是：

```text
Staff

↓

Clef

↓

Note

↓

Beam

↓

Tie
```

没有

```text
Numbered Note
```

这个概念。

因此不能直接改。

***

## ② OpenSheetMusicDisplay（OSMD）❌

OSMD 基于 MusicXML。

只能：

```
MusicXML

↓

五线谱
```

不能：

```
MusicXML

↓

简谱
```

## 我认为这是你平台最值得投入的地方

结合你准备做的是**AI 钢琴学习平台**，我认为**不要把渲染建立在某个现有框架上，而是建立在自己的数据模型上**：

- **输入层**：MusicXML、MIDI、PDF（经 OMR）、你的 Piano DSL。
- **统一 AST（抽象语法树）**：把所有输入转换为同一种内部表示。
- **输出层**：
  - SVG 简谱（你自己的 Renderer）
  - 五线谱（OSMD）
  - MIDI 播放
  - PDF 导出

这样以后无论 AI 生成乐谱、老师上传 MuseScore，还是用户编辑简谱，都只需要维护一套数据模型。

从目前开源生态来看，**自己实现简谱 Renderer 并不是重复造轮子，而是目前行业里大多数产品都在做的事情**。真正成熟、支持钢琴双手、指法、节奏的开源 Web 简谱渲染器，目前几乎没有。
