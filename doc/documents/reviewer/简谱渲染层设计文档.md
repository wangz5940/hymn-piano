# 练琴簿简谱渲染层设计文档

生成时间：2026-07-21

审核修订：2026-07-21

审核结论：总体架构方向正确，以下内容已经作为实施前置条件纳入本文：

- Render AST 只保存稳定的音乐语义；当前步骤、完成状态、指法开关和键位辅助属于 View State。
- 拍号使用完整 `meter: { beats, beat_unit }`；时值先换算为四分音符单位，再决定下划线和延音横线。
- 调式至少区分大调与自然小调，并允许显式 `scale_intervals`，避免只靠 `tonic_midi` 错拼音级。
- `silence`、`rest`、`sustain` 和正式 `tie` 分别建模；单手空数组不再推断为休止符。
- 布局按容器宽度分系统，每个系统单独生成 SVG；SSR 使用稳定默认宽度，浏览器端按宽度分桶重排。
- Hanon 001 的 v1 验收是完整显示、不中断并输出 warning；缺少 voice 的源数据不承诺恢复原始多声部语义。
- 指法圆圈默认都在音符上方，仅在碰撞时避让，不按左右手固定上下位置。

## 1. 结论

练琴簿的简谱渲染层应采用自研 Renderer，而不是把 VexFlow、OSMD 或其他五线谱引擎改造成简谱引擎。

原因很明确：

- VexFlow 的核心抽象是 Staff、Clef、Note、Beam、Tie，没有 Numbered Note 的一等模型。
- OSMD 的优势是 MusicXML 到五线谱 SVG，适合作为原谱对照，不适合作为简谱渲染核心。
- 当前项目已经有可用的结构化数据：教材 JSON 的 `jianpu_score` 和课程练习的 `expected_step`。真正缺的是统一的简谱布局层，而不是新的乐谱源格式。

建议路线：

```text
jianpu_score / practice_score
        |
        v
Semantic Render AST
        |
        v
Validation
        |
        v
Width-aware System Layout
        |
        v
Per-system SVG Renderer
        |
        v
Stateless React View Adapter
```

这个设计保留现有数据模型，只在渲染层增加规范化和布局计算。后续无论输入来自 MusicXML、MIDI、PDF OMR、AI 生成 DSL，最终都转换到同一套 Render AST。

## 2. 当前数据模型评估

### 2.1 教材简谱 JSON

`dist/materials/jianpu/hanon/001.json` 代表了当前教材简谱数据结构：

```ts
interface jianpu_score {
  schema_version: "1.0";
  segment_id: string;
  key_signature: string;
  tonic_midi: number;
  time_signature: string;
  measures: jianpu_measure[];
}

interface jianpu_measure {
  index: number;
  number: string;
  directions: string[];
  events: jianpu_event[];
}

interface jianpu_event {
  onset_beats: number;
  duration_beats: number;
  right_notes: number[];
  left_notes: number[];
  chord?: string;
}
```

Hanon 001 样本特征：

- `schema_version`: `1.0`
- `segment_id`: `hanon.segment.001`
- `key_signature`: `C 大调（1 = C）`
- `tonic_midi`: `60`
- `time_signature`: `2/4`
- 小节数：29
- 事件数：233
- 右手有音事件：106
- 左手有音事件：228
- 双手同事件发声：101
- 最大同一事件音数：5
- 音域：MIDI 36 到 83
- 出现的时值：`0.25`、`0.5`、`1`

这个结构已经能支持：

- 调号和拍号
- 小节
- 左右手
- 起拍位置
- 音符时值
- 和弦音
- 和弦标记
- 高低音点的派生
- 升降号的派生

暂时缺少：

- 指法
- 声部 voice/layer
- 连音线、圆滑线、断奏、重音
- 踏板、反复、段落结构
- 每个音独立时值
- 明确休止符类型

### 2.2 课程练习数据

`PracticeScore.tsx` 使用的是课程练习模型：

```ts
interface expected_step {
  id: string;
  measure_index: number;
  beat_index: number;
  beat_in_measure?: number;
  notation: string;
  note_names: string[];
  notes: number[];
  fingerings?: note_fingering[];
  held_hands?: Array<"right" | "left">;
  hand: "right" | "left" | "both";
  duration_beats: number;
  match_mode: "single_note" | "chord";
}
```

它比教材 JSON 多出：

- 指法 `fingerings`
- 小节内起拍 `beat_in_measure`
- 手别 `hand`
- 延音保持 `held_hands`
- 练习判定所需的 `match_mode`

`practice_score` 还包含可变拍号曲目所需的 `measure_beats`。授权导入源数据另有
`measure_beat_units`，实施时必须透传到 `practice_score`，否则 6/8 等非四分音符拍号
无法正确解释时值。

这说明渲染层不能只绑定教材 JSON。更合理的做法是定义一个中间 Render AST，让教材 JSON 和课程练习都先转换到同一套渲染模型。

## 3. 当前实现的问题

当前项目里存在两套简谱渲染：

- `src/pages/JianpuLibrary.tsx` 内部的 `JianpuScore`、`JianpuMeasure`、`JianpuEvent`、`JianpuNote`
- `src/components/PracticeScore.tsx` 内部的 `JianpuScore`、`JianpuMeasure`、`JianpuEvent`、`JianpuNote`

主要问题：

1. MIDI 到简谱的转换重复实现，且升号显示不一致。练习页使用 `#`，教材页使用 `♯`。
2. 当前排版依赖 CSS flex 顺排，无法准确表达同一小节内不同声部的重叠起拍。
3. 教材页按 2 小节切系统，练习页按 4 小节切系统，系统换行策略写死。
4. 左右手行可以对齐，但小节线还不是严格的双手贯穿式布局。
5. 指法、时值线、高低音点、延音横线、升号位置目前散落在组件和 CSS 中，没有统一规格。
6. 空手事件被显示成休止点，但当前数据里的空数组很多时候只是另一只手不发声，不一定是正式休止符。
7. Hanon 001 中部分事件的 `onset_beats + duration_beats` 超过 `2/4` 的标准 2 拍，说明数据里可能存在多声部顺序化结果。渲染层需要兼容并报警，长期应由转换层补充 voice 信息或修正 onset。

## 4. 渲染目标

### 4.1 首期目标

首期目标是专业、稳定地渲染钢琴双手简谱，覆盖当前课程和教材页面。

必须支持：

- 标题、调号、拍号
- 双手谱大括号
- 右手行、左手行
- 小节线和终止线
- 小节编号
- 小节内按起拍位置对齐
- 数字音符 1-7
- 升号位于数字左上角
- 高低音点
- 和弦纵向堆叠
- 0.5、0.25、0.125 等短时值下划线
- 长时值右侧延音横线
- 指法圆圈，支持全局隐藏
- 当前练习步骤高亮
- 已完成步骤状态
- 键位辅助可选显示

### 4.2 非首期目标

首期不做：

- 完整五线谱替代。五线谱仍由 OSMD 负责。
- 音乐排版级自动避让的全部复杂场景。
- 反复记号、跳房子、踏板的完整规范。
- Canvas 渲染。首期以 SVG 为主，便于精确布局、导出和测试。

## 5. 推荐模块结构

建议新增渲染模块：

```text
src/features/jianpu/render/
  model.ts
  pitch.ts
  normalizePracticeScore.ts
  normalizeJianpuScore.ts
  validate.ts
  layout.ts
  JianpuSvg.tsx
  JianpuRenderer.tsx
  jianpuRenderer.css
  index.ts
```

职责划分：

- `model.ts`: 定义 Render AST 和 Layout Box 类型。
- `normalizePracticeScore.ts`: 把 `practice_score` 转换为 Render AST。
- `normalizeJianpuScore.ts`: 把 `jianpu_score` 转换为 Render AST。
- `pitch.ts`: 统一 MIDI 到简谱音级、升降号、高低音点转换。
- `validate.ts`: 检查小节时值、重叠、缺失字段、异常 onset。
- `layout.ts`: 无 React 依赖的纯函数，输入 AST 和宽度，输出按系统拆分的坐标。
- `JianpuSvg.tsx`: 把单个 System Box 绘制成 SVG。
- `JianpuRenderer.tsx`: 处理容器宽度、View State 和按系统延迟渲染。
- `jianpuRenderer.css`: 只负责主题、状态、容器和非几何样式。
- `index.ts`: 统一导出公共契约。

## 6. Render AST 设计

### 6.1 顶层结构

```ts
export interface jianpu_render_score {
  id: string;
  title?: string;
  key_signature: string;
  tonic_midi: number;
  scale_intervals: readonly number[];
  accidental_preference: "sharp" | "flat";
  time_signature: string;
  measures: jianpu_render_measure[];
}

export interface jianpu_meter {
  beats: number;
  beat_unit: number;
}

export interface jianpu_render_view_state {
  mode: "reading" | "practice";
  current_event_id?: string;
  completed_event_ids?: ReadonlySet<string>;
  show_fingerings: boolean;
  show_keyboard_aid: boolean;
}
```

### 6.2 小节结构

```ts
export interface jianpu_render_measure {
  id: string;
  index: number;
  number: string;
  directions: string[];
  meter: jianpu_meter;
  content_beats: number;
  warnings: jianpu_render_warning[];
  right: jianpu_render_hand_event[];
  left: jianpu_render_hand_event[];
  chord_labels: jianpu_chord_label[];
}
```

说明：

- `declared_beats` 来自拍号，例如 `2/4` 是 2。
- `content_beats` 来自事件最大结束位置。
- 渲染网格默认使用 `declared_beats`，但当事件超出小节时，渲染层需要记录 warning，并选择裁剪、压缩或扩宽。
- `right` 和 `left` 拆成独立手部事件，避免一个事件同时控制两只手的布局。

### 6.3 手部事件

```ts
export interface jianpu_render_hand_event {
  id: string;
  hand: "right" | "left";
  kind: "note" | "rest" | "sustain";
  onset_beats: number;
  duration_beats: number;
  notes: jianpu_render_note[];
  voice?: number;
  tie?: jianpu_tie_info;
  source_ref: jianpu_source_ref;
}

export interface jianpu_tie_info {
  id: string;
  role: "start" | "continue" | "stop";
  source_event_id?: string;
}

export interface jianpu_source_ref {
  source: "jianpu_score" | "practice_score";
  event_index: number;
  step_index?: number;
}

export interface jianpu_chord_label {
  id: string;
  onset_beats: number;
  text: string;
}
```

规则：

- `kind === "note"` 才允许 `notes.length > 0`，表示实际音符或和弦。
- `kind === "rest"` 才显示休止符。当前 v1 输入没有显式 rest 字段，因此规范化层默认不推断 rest。
- `kind === "sustain"` 用于练习模型里的 `held_hands`，表示保持前音，不等同于正式延音线。
- `tie` 只表示乐理上的延音线；没有可靠 tie 来源时不得由 `held_hands` 推断。
- 教材 JSON 当前没有明确 rest 字段，不能把所有空数组都渲染成正式休止符。

### 6.4 音符结构

```ts
export interface jianpu_render_note {
  midi: number;
  degree: "1" | "2" | "3" | "4" | "5" | "6" | "7";
  accidental: "" | "#" | "b" | "natural";
  octave_offset: number;
  finger?: 1 | 2 | 3 | 4 | 5;
  keyboard_label: string;
}
```

规则：

- `degree`、`accidental`、`octave_offset` 由 `midi`、`tonic_midi` 和 `scale_intervals` 派生。
- 默认大调音阶为 `[0, 2, 4, 5, 7, 9, 11]`，自然小调为
  `[0, 2, 3, 5, 7, 8, 10]`；输入可显式覆盖。
- 升号统一使用 `#`，显示在数字左上角。
- 高音点显示在数字上方，低音点显示在数字下方。
- 指法不写进 `degree`，而是独立绘制为圆圈。

## 7. 数据转换策略

### 7.1 从 `jianpu_score` 转换

教材 JSON 转换流程：

```text
jianpu_score
  -> parse_time_signature
  -> split right_notes / left_notes
  -> midi_to_jianpu_note
  -> collect chord labels
  -> validate measure timeline
  -> jianpu_render_score
```

转换规则：

- 每个原始 `jianpu_event` 生成 0-2 个 `jianpu_render_hand_event`。
- `right_notes.length > 0` 时生成右手事件。
- `left_notes.length > 0` 时生成左手事件。
- 两手都为空时保留静默时间槽，但 v1 不推断为显式休止；源数据升级后才由
  `rest: true` 生成 `kind: "rest"`。
- `chord` 放入 `chord_labels`，位置使用原事件的 `onset_beats`。
- `directions` 放入小节顶部。

### 7.2 从 `practice_score` 转换

课程练习转换流程：

```text
practice_score.steps
  -> group by measure
  -> split by hand
  -> attach fingerings
  -> attach held_hands as sustain
  -> jianpu_render_score
```

转换规则：

- `hand === "right"`：全部音符归右手。
- `hand === "left"`：全部音符归左手。
- `hand === "both"`：优先按 `fingerings.hand` 拆分；没有完整指法时按音高拆分，最高音归右手，其余归左手。
- `fingerings` 按 MIDI 精确匹配到音符。
- `held_hands` 转成 `sustain`。
- `current_step_index` 不进入 AST；React 适配层把它转换为 `current_event_id` 和
  `completed_event_ids`。
- `beat_in_measure` 优先作为 onset；没有时才按稳定的累计拍位置回退。
- 每小节的 `beat_unit` 来自 `measure_beat_units`，缺失时回退到顶层拍号分母。

## 8. 布局引擎设计

### 8.1 不再用 flex 顺排作为核心布局

当前 flex 顺排适合简单一行音符，但不适合 Hanon 001 这类数据：

- 存在同一小节多声部重叠。
- 右手长音会和左手短音同时发生。
- 部分事件的 onset 超过 `2/4` 的声明长度。

新的布局必须基于时间坐标：

```ts
x = measure_x + measure_padding_left
  + onset_beats / layout_beats * measure_content_width;

width = duration_beats / layout_beats * measure_content_width;
```

其中 `layout_beats` 默认是 `meter.beats`。当 `content_beats > meter.beats` 时：

1. 记录 warning。
2. 阅读模式可用 `max(declared_beats, content_beats)` 扩宽小节，避免音符被截断。
3. 练习模式优先使用 `declared_beats`，超出部分显示为跨小节延音或异常标记，避免破坏节拍训练。

### 8.2 坐标层级

```text
ScoreBox
  SystemBox[]
    BraceBox
    MeasureGroupBox[]
      MeasureBox
        BarLineBox
        DirectionBox
        ChordLabelBox
        HandRowBox(right)
          EventBox[]
            NoteBox[]
            FingeringBox[]
            DurationLineBox[]
            HoldLineBox
        HandRowBox(left)
```

### 8.3 系统换行

不要写死每行 2 小节或 4 小节。

推荐策略：

1. `ResizeObserver` 获取容器宽度，并按 40px 分桶，避免每变化 1px 都重新布局。
2. SSR 和测试使用稳定默认宽度 960px。
3. 根据宽度确定 `target_system_width`。
4. 每个小节先计算 `min_measure_width`。
5. 按小节逐个加入当前系统，超过宽度则换行。
6. 阅读模式可以更密，练习模式应更疏。
7. 每个系统独立生成一个 SVG；长曲系统使用 `content-visibility: auto`。

小节最小宽度计算：

```text
min_measure_width =
  base_padding
  + unique_onset_count * min_slot_width
  + max_chord_stack_extra
  + chord_label_extra
```

Hanon 001 的最小 slot 应按 `0.25` 拍处理，因为它大量使用 `duration_beats = 0.25`。

### 8.4 双手对齐

双手谱必须满足：

- 同一个小节的右手和左手共享同一套 x 坐标。
- 小节线贯穿右手行和左手行。
- 大括号跨越整个系统高度。
- 右手行和左手行的 measure box 宽度完全一致。

这意味着不能让右手行和左手行分别 flex。必须先算 measure box，再把两个 hand row 放进去。

## 9. 简谱元素绘制规范

### 9.1 数字音符

数字使用宋体或兼容 serif：

```text
font-family: "Songti SC", ui-serif, serif
font-size: 24-30px
font-weight: 700
```

同一事件多个音符时按音高纵向堆叠：

- 低音在下，高音在上。
- 和弦整体居中。
- 每个音保留自己的高低音点和升降号。

### 9.2 升降号

升号必须位于数字左上角：

```text
accidental_x = note_x - accidental_offset_x
accidental_y = note_y - accidental_offset_y
```

当前项目统一先支持 `#`。后续如需要支持降号和还原号，加入 `b` 和 `natural`。

### 9.3 高低音点

规则：

- `octave_offset > 0`：在数字上方绘制同数量圆点。
- `octave_offset < 0`：在数字下方绘制同数量圆点。
- 多个点水平居中排列。
- 点不能参与数字本身宽度计算，但要参与碰撞检测。

### 9.4 时值下划线

时值先换算为四分音符单位：

```text
quarter_units = duration_beats * 4 / meter.beat_unit
```

| quarter_units | 含义 | 下划线 |
| --- | --- | --- |
| `1` | 四分音符 | 0 条 |
| `0.5` | 八分音符 | 1 条 |
| `0.25` | 十六分音符 | 2 条 |
| `0.125` | 三十二分音符 | 3 条 |

绘制规则：

- 下划线位于数字下方。
- 和弦时下划线覆盖整个和弦组宽度。
- 低音点优先靠近数字，下划线再向下避让。
- `1/3`、`2/3` 等 3:2 三连音时值先还原名义音符时值；八分三连音使用 1 条
  下划线，不能按十六分音符画 2 条。

### 9.5 长时值延音横线

`duration_beats > 1` 时在数字右侧同高度绘制延音横线：

```text
hold_x = note_right + 4
hold_y = note_baseline
hold_width = duration_width - note_width - gap
```

要求：

- 横线不能跑到数字下方。
- 横线与数字保持同一视觉基线。
- 跨小节延音需要拆成当前小节内横线和下一小节延续标记。

### 9.6 指法圆圈

指法显示策略：

- `show_fingerings === false` 时彻底不渲染任何指法节点。
- 左右手默认都在音符上方，与《小星星》目标图一致。
- 如果与高低音点、下划线冲突，则使用自动避让。
- 和弦中每个音可以独立显示一个指法圆圈。

圆圈规格：

```text
diameter: 14-16px
stroke: 1px
font-size: 9-10px
```

### 9.7 休止和空手

必须区分两种情况：

1. 真实休止：需要显示休止符或休止点。
2. 某只手在另一个手发声时为空：不显示休止点，只保留布局空位。

当前 `jianpu_score` 没有显式 rest 字段，所以规则是：

- `right_notes` 和 `left_notes` 都为空：只保留静默时间槽，不推断真实休止。
- 单手为空但另一手有音：该手不渲染休止点。
- `practice_score` 中 `held_hands` 表示延音保持，不是普通休止。
- `rest` 必须来自未来 v2 的显式字段。

## 10. Hanon 001 的特殊处理

Hanon 001 是非常好的压力测试样本。

样本中有 9 个小节的 `content_beats` 不等于 `2/4` 声明的 2 拍，其中小节 3、6、8、10、15、17、24、26、27 出现超出或不足。

设计上不应让渲染器静默吞掉这些异常。应输出结构化 warning：

```ts
interface jianpu_render_warning {
  code:
    | "measure_content_exceeds_declared_beats"
    | "measure_content_shorter_than_declared_beats"
    | "event_overlaps_existing_event"
    | "missing_voice_information";
  measure_index: number;
  message: string;
}
```

渲染策略：

- 阅读模式：优先完整显示所有事件，小节可按 `content_beats` 扩宽。
- 练习模式：优先保证节拍一致，超出声明拍数的事件标记为数据异常或跨小节候选。
- 数据生成链路后续应补充 `voice` 字段，避免把多声部按顺序堆到同一小节时间线之后。
- v1 验收只要求 29 小节完整显示、页面不中断并输出 warning；在缺少 voice 的前提下，
  不承诺恢复异常小节的原始多声部音乐语义。

## 12. SVG Renderer 选择

建议使用 SVG 作为首期渲染目标。

优势：

- 坐标精确，适合乐谱排版。
- 可导出图片或 PDF。
- 可用快照测试验证。
- React 中可直接渲染。
- 高亮、hover、当前步骤状态容易通过 class 控制。

Canvas 暂不作为主路线，因为 Canvas 对文本测量、可访问性、交互状态和测试都更麻烦。

## 15. 验收标准

首期渲染层完成时，应满足：

1. Hanon 001 能完整渲染 29 个小节。
2. 双手小节线严格对齐。
3. 同一 onset 的左右手音符水平对齐。
4. `#` 位于数字左上角。
5. `duration_beats = 0.25` 显示两条下划线。
6. `duration_beats = 0.5` 显示一条下划线。
7. `duration_beats > 1` 的延音横线位于数字右侧同高度。
8. 高音点和低音点位置稳定，不挤压数字。
9. 指法关闭时不渲染任何指法节点。
10. 教材页和练习页共用同一套 MIDI 到简谱转换逻辑。
11. 对 Hanon 001 中异常小节输出 warning，但页面不崩溃。
12. OSMD 原谱对照不受影响。
13. A 自然小调按自然小调音阶拼写。
14. 6/8 时值线依据 `beat_unit = 8` 计算。
15. 当前步骤变化不触发 AST 重新规范化和布局。
16. 单手无音和双手静默槽都不被误画为显式休止。
17. 每个系统独立 SVG，并具备 `role="img"`、文本替代和稳定 SSR 输出。

## 16. 最终建议

当前数据模型不需要推倒重来。真正应该投入的是渲染层：

- 保留 `jianpu_score` 和 `expected_step`。
- 新增统一 Render AST。
- 用 SVG 做精确布局。
- 用时间坐标替代 flex 顺排。
- 把升号、延音线、时值线、指法、双手大括号这些简谱规则沉到 Renderer。

这条路线与 reviewer 的判断一致：练琴簿不应该把简谱建立在五线谱框架上，而应该建立在自己的数据模型和渲染模型上。
